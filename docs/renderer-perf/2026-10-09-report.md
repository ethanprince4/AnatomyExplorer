# Renderer performance: results (2026-10-09)

Branch `claude/renderer-perf`, local commits only (nothing pushed). Design and rules: `2026-10-09-diagnosis.md`.
Every accepted picture difference: `port-changes.md`. What to run on a Mac: `mac-checklist.md`.
Nothing here has been measured on a Mac. The Intel UHD 770 in the build PC stands in for the M1, and the RTX 3080 is
the fast reference.

## Summary

- A new wgpu renderer for the model viewer ships in v4.0.6.
  - It is on by default on macOS and off elsewhere: Settings > Display > "Fast renderer for models (new)", setting
    `fast_renderer`.
  - It draws a visibility buffer (triangle ids + depth, 4x/8x MSAA), then shades each pixel once per covering
    triangle.
  - On top of that it culls hidden 64-triangle clusters on the GPU (frustum + two-phase hi-Z).
  - Models, `.npz` files and the existing LOD are untouched.
- RTX 3080 at 2560x1600, 4x MSAA, orbit: pancreas goes from 25.1 ms (GL) to 9.6 ms wall (5.2 ms GPU). Colon_wall and
  tongue_papillae improve by the same 3x.
- Triangle count is no longer the problem for one heavy model.
  - The 25M-triangle pancreas draws its ids in 2.9 ms (3080) and 25 ms (UHD).
  - The remaining frame time is pixel work: ambient occlusion and per-pixel shading. It costs the same for the
    1.7M-triangle tongue as for the 24.5M-triangle colon.
- M1 Air estimate, from the UHD (not measured): heavy models at full Retina with the default look land around
  20-40 ms, about 25-50 fps. That is not yet 60 fps; see "M1 MacBook Air: what to expect" for why and what is left.
- 250M triangles:
  - Culling keeps close and inside views fast (3080 ~8-10 ms, UHD 15-130 ms for the visibility part).
  - GPU memory is the hard limit on an 8 GB Air.
  - GPU memory per triangle went from 42.5 to 26 bytes. That fits a 16 GB Air but not an 8 GB one.
  - Compression stage 1 (about 19 B, in progress) is not enough for 8 GB either; stage 2 (about 15 B, designed, not
    built) would be.

## How to use it

| Switch | Values | Effect |
|---|---|---|
| Settings > Display > "Fast renderer for models (new)" (`fast_renderer`) | on by default on macOS, off elsewhere | Picks the model viewer's renderer for models opened after the change (`app/ui/model_view.py renderer_backend`). Any wgpu failure falls back to OpenGL and logs the reason once (`wgpu renderer unavailable, using OpenGL`). Models with alpha-cut textures always use OpenGL. |
| `ANATOMY_RENDERER` | `opengl`, `wgpu` | Overrides the setting. |
| `ANATOMY_CULL` | `auto` (default), `on`, `off` | GPU cluster culling. `auto` culls frames that draw at least `ANATOMY_CULL_MIN_TRIS` triangles (default 4,000,000) of static models (no morph, no procedural animation). |
| `ANATOMY_CULL_BUDGET` | triangles, default 8,388,608 (96 MiB) | Size of the culler's compact index buffer. Visible clusters beyond it are drawn by the slower vertex-pulled path; `0` = pulled only. |
| `ANATOMY_AO_SCALE` | `gi` (default), `full`, `half` | `gi`: indirect-light part of SSAO at half resolution (listed in port-changes.md). `full`: everything full resolution (the GL picture). `half`: AO and GI both half resolution, faster, slightly softer; opt-in, to be judged by eye on a Mac. |
| `ANATOMY_WGPU_ADAPTER` | substring, e.g. `UHD` | Pick a GPU. |
| `ANATOMY_WGPU_LIMITS` | `apple7` | Emulate the M1's limits on another GPU, for tests (`ANATOMY_WGPU_APPLE7_BUFFER_MB`, default 1024). |
| `ANATOMY_PRESENT_MODE` | `async` (default), `sync` | How the frame reaches the Qt widget. |

## What was built, in order

| Stage | Commit(s) | What it does |
|---|---|---|
| Fixes that hold for both renderers | earlier commits | Atlas labels orbit 17.5 -> 6.0 ms; prepared-model cache (pancreas load 7.7 -> 0.39 s); UI scaling; atlas 65,536 cap. |
| wgpu host, device, Qt embedding | 2fadaa7 and others | Offscreen render, asynchronous double-buffered readback into a Qt widget (overlays and labels blend correctly). |
| Visibility buffer + per-pixel shading | b7a2b99, 1e88d79, 0a608ae, 8f21411 | One id+depth pass, then shading per pixel (per covering triangle), instead of shading every fragment of every tiny triangle. The shading pass is compiled without the look features no part uses (`FEAT_*` constants). |
| All existing passes ported | a2549c6, 5d2c76d, ea38826, eabc196, 7803a57, f2fbb5f | Ghosting (OIT), morph, animation, textures, cut faces (caps), SSAO + GI, edges, picks. |
| Geometry layout v2 | 273b4ae, 29d0ec5 | One packed buffer per geometry page (up to 4 pages); at most 7 storage buffers per shader stage, so it runs within Metal's limits. |
| GPU cluster culling | c928295, 66789e2, f617722, ed9b4a3, df2659f | 64-triangle clusters, frustum + two-phase hi-Z; visible clusters are gathered into a bounded index buffer and drawn indexed. Ids decode back to the original triangle for shading and picks. |
| Release v4.0.6 | (this branch, merged to main) | Settings switch, on by default on macOS; the WGSL shaders are bundled in the installers (`packaging/AnatomyExplorer.spec`). |

## Speed: model viewer, 2560x1600, 4x MSAA (the Air's setting)

`tools/perf/gpu/frame_bench.py`: 120-frame orbit, default camera, the model fills most of the screen.
GL numbers are from `baseline-summary.md` (same size, same MSAA). GL cannot run on the UHD in this PC, so the UHD
column compares the first wgpu port with today.

### RTX 3080

| Model | Triangles | GL orbit ms (wall) | wgpu orbit ms (wall) | wgpu GPU ms | of which: ids (vis) | geom | ssao | shade |
|---|---|---|---|---|---|---|---|---|
| pancreas | 25.2M | 25.1 | 9.6 | 5.2 | 2.9 | 0.5 | 0.9 | 0.9 |
| colon_wall | 24.5M | 31.2 | 10.7 | 7.6 | 2.2 | 0.4 | 2.2 | 2.7 |
| tongue_papillae | 1.7M | 21.3 | 9.8 | 8.0 | 3.4 | 0.4 | 2.6 | 1.6 |

On the 3080, wall time is above GPU time because of the Windows readback into the Qt widget (about 3-4 ms).

### UHD 770 (integrated, the M1 stand-in)

| Model | First wgpu port, GPU ms | Today, GPU ms | Today, wall ms | ids (vis) | geom | ssao | shade |
|---|---|---|---|---|---|---|---|
| pancreas | 105 | 69.3 | 64.2 | 24.7 | 7.2 | 13.3 | 21.8 |
| colon_wall | 176 | 118.1 | 102.0 | 20.9 | 13.1 | 35.9 | 45.9 |
| tongue_papillae | 166 | 122.9 | 112.2 | 20.6 | 13.1 | 43.5 | 43.3 |

The morph/animation constants (df16e1e, a separate bench run, GPU ms) bring tongue_papillae 130.8 -> 122.6,
colon_wall 119.0 -> 109.9 and pancreas 66.8 -> 63.6. Geom and shade drop by about 4-5 ms each; the RTX 3080 is
unchanged.

Culling on vs off for the same frames: UHD pancreas ids 51.4 -> 22.6 ms, colon 69.3 -> 20.4, duodenum 58.9 -> 25.9;
3080 6.7 -> 2.0 ms (`cull_check`, LOD on).

### Where the UHD time goes now (tongue_papillae, 4x, 128.6 ms static frame)

- SSAO 45 ms (it does not depend on MSAA):
  - AO, 32 taps per pixel: 20.0 ms
  - GI at half resolution: 12.7 ms
  - two blurs: 8.8 ms
  - upsample and packing: 3.9 ms
- Shading 45 ms:
  - triangle setup + attributes: 14.5 ms
  - lighting: 13.5 ms
  - the tissue-detail noise of the look (two fbm noise evaluations, pure arithmetic): 14.8 ms
  - id loads: 2.7 ms
  - Pixels shade 1.18 triangles on average, so multi-triangle pixels are not the cost.
- Ids 21.6 ms and geometry resolve 13.8 ms.

All of this scales with the number of pixels, not triangles. At 8x MSAA (standard-DPI screens), ids, geom and
shade grow (UHD tongue 128.6 -> 187.7 ms).

## M1 MacBook Air: what to expect (estimate, not measured)

- **Basis.**
  - Arithmetic: the M1's GPU has about 3x the UHD 770's (7-core Air about 2.3 TFLOPS against about 0.74).
  - Memory bandwidth: about the same (68 GB/s).
  - Most of the frame above is arithmetic, so dividing the UHD's GPU time by about 3 is a rough guide.
- **Frame time.**

  | Model | Estimated frame | Estimated rate |
  |---|---|---|
  | pancreas | about 23 ms | about 43 fps |
  | colon_wall | about 35-40 ms | 25-30 fps |
  | tongue_papillae | about 35-40 ms | 25-30 fps |

  These assume full Retina, 4x MSAA and the default look, and include the morph/animation constants.
- **Retina, 4x MSAA.**
  - The app renders 2560x1600 with 4x MSAA on the Air: 16.4M samples per frame.
  - Ids and depth for those samples are written to memory and read back (about 130 MB each way).
  - A tile GPU could keep them on chip, but wgpu has no tile shaders. That is about 4 ms per frame on the M1, and
    it is a limit of wgpu, not of the chip.
- **What is left before the chip is the limit**, all invisible, ranked by expected gain on the UHD (divide by
  about 3 for the M1):
  1. AO loop arithmetic: -4 to -8 ms.
  2. Blur: about -3 ms.
  3. GI loop hoisting: -1 to -2 ms.
  4. Fusing the depth packing into the geometry resolve: -0.8 ms, and 65 MB less traffic on the M1.
  5. Shading blend order: -0.5 to -1 ms.

  Together about 10-15 ms on the UHD, so roughly 3-5 ms on the M1. After that, what remains is the per-pixel
  arithmetic of the look itself (32 AO taps, GI, three lights, the tissue-detail noise) over 4.1M pixels.
- **Look-changing options**, for the user to decide by eye on a Mac: `ANATOMY_AO_SCALE=half` (UHD tongue SSAO
  chain 68 -> 31 ms), or a lower render scale.
- **Run `mac-checklist.md` item 10 first**: these estimates may be off in either direction. For example, Apple's
  shader compiler may handle the noise functions differently, and Apple GPUs report no timestamps inside passes, so
  the Mac numbers will be wall times.

## The 250M-triangle scale

### Speed: visibility + culling only (no SSAO or shading), stress scene

The stress scene is 8 copies of pancreas, 236.9M triangles, at 2560x1600. The copies share one set of GPU buffers,
so memory at 250M is computed below, not measured. Times are ms per frame while moving.

| View | GPU | Culling only (LOD off) | Culling + existing LOD | Everything drawn, no culling (LOD off / on) |
|---|---|---|---|---|
| near (scene fills the view, mostly occluded) | RTX 3080 | 10.4 | 7.8 | 67.7 / 43.9 |
| near | UHD 770 | 129.8 | 76.8 | 249.7 / 166.6 |
| inside (camera among the structures) | RTX 3080 | 0.7 | 0.7 | 31.0 / 31.1 |
| inside | UHD 770 | 14.7 | 14.7 | 238.3 / 238.1 |

- Add the per-pixel passes from the tables above for a whole frame: 3080 about 2-5 ms, UHD 40-100 ms.
- Culling never removed a visible pixel: `cull_check correct` shows 0 false-cull pixels on 4 models x 2 GPUs, and
  the culled and unculled frames give the same ids except exact depth ties.
- **Open item, zoomed out on integrated GPUs.** Zoomed out with the whole 237M scene in view (the case we agreed
  not to design for), the UHD is slower with culling than without: 118 ms against 78 ms with LOD.
  - Cause: hi-Z keeps about 5x more clusters than end up visible (thin layered anatomy leaks through the depth
    pyramid).
  - Those beyond the 8.4M-triangle budget go through the vertex-pulled draw, which costs 3 vertex invocations per
    triangle on integrated GPUs.
  - The 3080 is not affected (8.8 ms with culling against 22.0 ms without).
  - Fixes: a larger `ANATOMY_CULL_BUDGET` where memory allows, or switching a frame to the plain draw when last
    frame's visible set overflowed the budget by a wide margin. Neither is built.

### Memory and capacity

GPU memory per base triangle (pancreas, `S/gpu_port/mem/gpu_walk.py`). The existing LOD levels are included
(about 2.1 B/tri).

| | B/tri | 250M triangles | + screen targets and culler budget (2560x1600, 4x) |
|---|---|---|---|
| Before culling memory work | 42.5 | 10.6 GB | about 11.1 GB |
| v4.0.6 | 26.0 | 6.5 GB | about 7.0 GB |
| Stage 1 compression (in progress) | about 19-20 | about 4.9 GB | about 5.4 GB |
| Stage 2 compression (designed) | about 15 | about 3.75 GB | about 4.3 GB |

- Screen targets are about 0.4 GB:
  - ids and depth, 65 MB each at 4x;
  - the geometry resolve, 131 MB;
  - SSAO, shading and the hi-Z pyramid.
- The culler's budget is 96 MiB.
- An 8 GB Air leaves about 5 GB for the GPU after macOS and the app. Only stage 2 fits the full 250M atlas there.
- A 16 GB Air fits it from v4.0.6 on.
- The 250M figures are computed from the per-triangle numbers, not measured. The stress scene's 8 copies share one
  set of buffers.
- **Second limit, buffer size.**
  - One model's geometry may use at most 4 pages. Each page is one buffer of the adapter's maximum storage-binding
    size: 1 GiB on the UHD 770, and also on the `apple7` emulation.
  - With 1 GiB pages a single model holds about 165M triangles at 26 B/tri, about 215M after stage 1 and about
    285M after stage 2.
  - A bigger model raises `GeometryError` and falls back to OpenGL.
  - The real Metal page size is `mac-checklist.md` item 1.

## Cut views

Measured with a cut plane on pancreas, UHD 4x, 120-frame orbit:

| | GPU ms | Wall ms |
|---|---|---|
| without the cut | 69 | 65 |
| with the cut | 124 | 141 |

- **The clip discard in the visibility pass costs about 58 ms GPU** (ids pass 25 -> 87 ms).
  - Cause: a shader that can discard loses early depth rejection on that GPU.
  - Hardware clip planes would avoid it, but wgpu exposes them only on Vulkan/D3D12, not on Metal.
  - The portable fix: classify clusters against the plane. Fully kept clusters draw with the no-discard pipeline,
    fully cut ones are skipped, and only the few that straddle the plane use the discard pipeline. The picture
    stays the same. Not built.
- **The cut-face (caps) passes add little GPU time.** They do add wall time (about 24 ms on pancreas, 84 ms on
  tongue_papillae), most likely the CPU planning loop in `app/gpu/caps.py` (`CapPasses.plan`) that runs every
  frame. The caps passes are outside the GPU timestamps, so this is not yet proven. Caching the plan between
  frames when nothing changed is the likely fix.
- On the RTX 3080 a cut view costs 13.2 -> 17.7 ms.

## The existing LOD, truthfully

- `app/viewer/lod.py` builds coarser copies of large parts at load time.
- Each frame, for each part, the renderer picks the coarsest level whose error is at most one pixel on screen
  (`_lod_levels`). Parts are never dropped for being small.
- **This is a coarser copy of geometry.** It existed before this work and stays exactly as it was, in both
  renderers. The culler takes the parts and levels the renderer already chose.
- No new simplification of any kind was added. Every speed-up above is one of these:
  - skipping what cannot be seen (off screen, hidden behind visible geometry);
  - shading each pixel once instead of every fragment;
  - storing the same values more compactly;
  - doing the same arithmetic in a cheaper order.
- What the LOD buys at 250M:
  - It cuts the triangles submitted in the near view from 201M to 129M.
  - It makes the UHD near view 130 -> 77 ms.
  - It costs about 2.1 bytes per triangle of GPU memory.
- Results above are given with and without it.

## Picture fidelity

`port-changes.md` lists every place the wgpu picture can differ from GL, with sizes. In short:

- **Same GPU (RTX 3080).**
  - wgpu matches GL to within float rounding on interiors.
  - The residue sits on silhouette pixels, where a visibility buffer and GL's centroid shading place a lit edge
    differently, and on thin slivers smaller than an MSAA sample.
- **Picks.** Picks agree with GL on 160/160 samples (99.4% on one tongue state), using a single-sample re-draw at
  the picked pixel.
- **Culling on vs off.**
  - Ids are identical in 17 of 20 states.
  - The other 3 differ on at most 192 of 2.5M covered pixels, all exact ties between coplanar triangles.
  - Depth is identical.

## What is left, ranked by value for the M1 and the atlas

1. **Run `mac-checklist.md` on an M1 Air.** v4.0.6 is the renderer's first run on Metal (on by default on macOS),
   so this comes first. It has 10 items. Item 1 must show `prim_index` True, item 9 checks the
   culler's Metal-specific behaviour, and item 10 gives the real numbers. Nothing here is proven on Metal.
2. **Geometry compression stage 2** (positions quantised to 16 bits per axis in 64-vertex blocks, error held
   below 1/16 pixel at the closest zoom).
   - Designed; slots are already reserved in the page layout (S/gpu_port/l3/HANDOFF.md, `L3_prompt.md` step 3).
   - Needed for the full 250M atlas on an 8 GB Air.
3. **Cut views:** straddle classification (about -50 ms UHD on pancreas) and caching the caps plan.
4. **Zoomed-out overflow on integrated GPUs:** budget size or a per-frame fallback to the plain draw (see the open
   item under "Speed" above).
5. **Screen-space passes:** the 5 invisible items listed under the M1 section (about 10-15 ms UHD).
6. **`ANATOMY_CULL_MIN_TRIS`:** the 4M default was set before the bounded draw landed. tongue_papillae (1.7M) is
   faster culled than plain on both GPUs at 8x (UHD ids 20.5 -> 8.1 ms), so a lower default is likely better. It
   needs a 4x sweep that includes small models.
7. **Alpha-cut textures** in the wgpu frame. Today they fall back to OpenGL; no library model uses them yet.
8. **Atlas viewport.** The Z-Anatomy atlas (`app/viewport.py`, `app/renderer.py`) still uses OpenGL. The coming
   `.npz` atlas goes through the model viewer, which is the ported path.
